# NAMIR 3D Cutaway Mine Explorer — Source Package

Interactive 3D cutaway mine explorer built with **Three.js** and bundled with
**Vite**. Users orbit a 3D mine scene and click hotspots to open information
panels about products and solutions. Content (hotspots, descriptions, contacts,
colours) is driven by a CSV file, so most updates need no code changes.

**Version:** 1.0.3
**3D model:** 1.0.3 (Draco-compressed)

---

## 1. Prerequisites

- **Node.js 18 or newer** (includes `npm`). Download: https://nodejs.org/

This package does **not** include `node_modules/` (dependencies) or `dist/`
(the build output). Both are generated by the commands below.

## 2. Quick start

```bash
# 1. Install dependencies (first time only)
npm install

# 2. Run a local dev server with hot reload
npm run dev

# 3. Build the production site into dist/
npm run build
```

`npm run dev` prints a local URL (e.g. http://localhost:5173). `npm run build`
produces the deployable static site in `dist/`.

## 3. Project structure

```
src/                     Application source
  index.html             Page markup (entry point; Vite root)
  script.js              Main app: scene, hotspots, panels, model loading
  style.css              Core styles
  panel-styles.css       Side-panel styles
  z-index-fix.css        Layering fixes
static/                  Assets copied as-is into the build
  data/                  hotspots_multilang.csv  <- main content file
  images/                Icons, logos, SidePanelImages (WebP)
  models/glb/            3D model (Draco-compressed, loaded at runtime)
  textures/              Environment lighting (HDR)
  fonts/                 Fonts
model-source/            Uncompressed 3D model master (see section 5)
vite.config.js           Build config (root = src, output = dist)
```

## 4. Editing content (no code required)

Almost all on-screen content lives in **`static/data/hotspots_multilang.csv`**.
Each row is a hotspot. Key columns:

- **Category / Item** — grouping and item name (English), plus `_MN` columns for
  Mongolian.
- **Description** — panel body text (and `Description_MN`).
- **Image** — filename in `static/images/SidePanelImages/`. You may list a
  `.jpg` name; the app automatically serves the matching `.webp` (see section 6).
- **Icon / GroupIcon** — filenames in `static/images/Icons/`.
- **Color / TextColor / IconColor** — per-category theming (hex values).
- **Position / Camera / Target** — 3D coordinates for the hotspot and camera.
- **Phone / Email / Button URLs** — contact and link details.

After editing the CSV, run `npm run build` (or refresh `npm run dev`) to see
changes.

## 5. Updating the 3D model (Draco pipeline)

The app loads a **Draco-compressed** `.glb` from `static/models/glb/`. Draco
compression cuts the model from ~68 MB to ~30 MB. The decoder is already wired
up in `src/script.js`, so a compressed model "just works".

`model-source/` contains the **uncompressed master** for re-exporting or
re-compressing. To compress a new export:

```bash
npx @gltf-transform/cli draco input.glb output_draco.glb
```

Then:
1. Put `output_draco.glb` in `static/models/glb/`.
2. Update the filename in `src/script.js` (search for `gltfLoader.load(`).
3. `npm run build`.

## 6. Side-panel images

Images live in `static/images/SidePanelImages/` as **WebP** (converted from JPG
to reduce size by ~65%). The app derives the `.webp` name from whatever the CSV
lists, and preloads all panel images after the model loads so panels open
instantly. To add an image: save it as WebP here and reference it in the CSV.

## 7. Deployment

Run `npm run build` to produce the `dist/` folder — a self-contained static
site. Host it on any static web host, **served from the site root** (all asset
paths are absolute, so it must not sit in a sub-path).

Suitable hosts include **AWS Amplify**, **Netlify**, **Cloudflare Pages**,
**AWS S3 + CloudFront**, **Azure Static Web Apps**, or a traditional
**Apache / Nginx / IIS** web root. In each case, upload the **contents of
`dist/`** so that `index.html` is at the top level of the site.

## 8. Notes

- **Draco decoder** is loaded at runtime from Google's CDN
  (`https://www.gstatic.com/draco/...`), so the site needs outbound internet for
  the model to decode. For a fully offline build, the decoder can be bundled
  locally — ask the developer.
- **Browser requirement:** a modern browser with WebGL 2. The experience is
  GPU-accelerated 3D.
- `node_modules/` and `dist/` are intentionally excluded; regenerate with
  `npm install` and `npm run build`.
